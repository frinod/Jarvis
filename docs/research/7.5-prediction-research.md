### Known limitations

1. **`MockForecastingEngine` is the only implementation** — the real
   XGBoost models in `backend/models/` are never called by the AI runtime.
2. **`FeatureStore` extracts only raw numeric values** — no RSI, MACD, EMA,
   BB, ATR, or volume ratio features. The XGBoost models were trained on
   these indicators; feeding raw OHLCV will produce garbage predictions.
3. **`ConfidenceScorer` returns 0.5 neutral** when no inputs are provided —
   which is always the case since `MockForecastingEngine` is wired.
4. **`TraderAgent._generate_signal()` uses `context.confidence` as a proxy**
   — not the `ForecastingEngine` output.
5. **No model metadata loading** — `.meta` files exist alongside `.pkl` files
   but are never read. Feature names and training parameters are unknown
   to the runtime.
6. **No model for most Nifty 50 symbols** — only 12 symbols have models.
   The orchestrator handles 50+ symbols via live TA.

## 2. Research Findings

### 2.1 XGBoostForecastingEngine

The `.pkl` models are trained XGBoost classifiers. The `.meta` files
contain the feature list and training metadata.

**Phase 7 implementation**:
- Load `.meta` JSON to discover required feature names.
- Load `.pkl` model with `joblib.load()` or `pickle.load()`.
- `FeatureStore.build()` must produce features matching the `.meta` feature
  list exactly (same names, same order).
- `predict()` calls `model.predict_proba()` and maps to
  `PredictionDirection` (UP/DOWN/NEUTRAL).

**Python 3.7 compatibility**: `xgboost>=1.3` supports Python 3.7. The
existing models were trained with a compatible version (confirmed by `.meta`
files existing alongside `.pkl`).

**Verdict**: **implement `XGBoostForecastingEngine` in Phase 7**.

### 2.2 Feature Engineering Gap

The XGBoost models require technical indicator features (RSI, MACD, EMA,
BB, ATR, volume ratio). The current `FeatureStore` only extracts raw
numeric values from dicts.

**Required features** (from `orchestrator._fetch_stock_context()`):
- RSI, MACD, VWAP, ATR
- EMA9, EMA21, EMA50
- BB Upper, BB Lower
- Volume Ratio

These are already computed by `compute_technical_analysis()` in
`app/api/technical_analysis.py`. The gap is that `FeatureStore` does not
call this function — it only processes whatever dict it receives.

**Phase 7 fix**: add a `TechnicalFeatureExtractor` to `FeatureStore` that
accepts a candle list and calls `compute_technical_analysis()`, then maps
the result to the feature names expected by the XGBoost models.

**Verdict**: **implement `TechnicalFeatureExtractor` in Phase 7**.

### 2.3 Model Coverage Gap

Only 12 symbols have trained models. The orchestrator handles 50+ symbols.

**Options**:
- **A**: Use the nearest available model for uncovered symbols (e.g., use
  ICICIBANK model for HDFCBANK). Risk: feature distributions differ.
- **B**: Fall back to `ConfidenceScorer` TA-only path for uncovered symbols.
  Clean, safe, already implemented.
- **C**: Train new models for all Nifty 50 symbols. Out of scope for Phase 7.

**Verdict**: **adopt option B** — `XGBoostForecastingEngine.is_model_available()`
returns `False` for uncovered symbols; `ConfidenceScorer` uses TA-only path.

### 2.4 Confidence Aggregation

`ConfidenceScorer` weights: prediction(50%) + TA(30%) + sentiment(20%).

**Research finding**: for short-horizon (h3 = 3-period) predictions, TA
signals are more reliable than model predictions when the model was trained
on limited data. Recommended weights for Phase 7:

- When model available: prediction(50%) + TA(30%) + sentiment(20%) — keep current.
- When model unavailable: TA(70%) + sentiment(30%) — TA-dominant fallback.

This requires a `ScorerConfig` variant, not a code change.

### 2.5 Alternative ML Approaches (Research Only)

| Approach | Quality | Complexity | Python 3.7 | Phase |
|----------|---------|-----------|------------|-------|
| XGBoost (current models) | Good | Low | ✅ | 7 |
| LightGBM | Good | Low | ✅ | 7 (optional) |
| LSTM / GRU | Better for sequences | High | ✅ | 8 |
| Transformer (TFT) | Best for time series | Very high | ✅ | 9 |
| Prophet (Facebook) | Good for trends | Medium | ✅ | 8 |

**Verdict**: use existing XGBoost models in Phase 7. No new model training.
LSTM/Transformer deferred to Phase 8 when more training data is available.

### 2.6 Prediction Caching

XGBoost inference is fast (~1–5 ms per prediction). However, feature
extraction from candle data takes ~50–200 ms. Cache the `FeatureVector`
per symbol per candle timestamp to avoid re-extraction within the same
session.

**Verdict**: **implement feature vector cache in Phase 7** as a simple
`dict[symbol → (timestamp, FeatureVector)]` in `XGBoostForecastingEngine`.

## 3. Recommended Architecture for Phase 7

```
TraderAgent.execute(ctx)
  └── FeatureStore.build_from_candles(candles)
        └── TechnicalFeatureExtractor.extract(candles)
              └── compute_technical_analysis(candles)   ← existing function
              └── map to model feature names from .meta
  └── XGBoostForecastingEngine.predict(features, model_name=symbol)
        └── load model from backend/models/{symbol}_h3_xgb.pkl
        └── model.predict_proba(features.to_list(meta_keys))
        └── return PredictionResult(direction, magnitude, confidence)
  └── ConfidenceScorer.score(prediction, ta_signal, sentiment)
        └── return ScoredResult.confidence
  └── TradeSignal(direction, confidence, rationale)
```

- `ConfidenceScorer` — no changes (new `ScorerConfig` variant is additive).
- `FeatureVector` data model — no changes.
- All existing tests — no modifications needed.

## 4. Phase 7 vs Phase 8 Scope

### Phase 7
- `XGBoostForecastingEngine` loading existing `.pkl` models
- `TechnicalFeatureExtractor` mapping TA indicators to model features
- Feature vector cache per symbol
- `TraderAgent` wired to real prediction pipeline
- TA-only fallback for uncovered symbols

### Phase 8+
- New model training (LSTM, LightGBM, Prophet)
- Nifty 50 full coverage
- Online learning / model updates from trade outcomes
- Ensemble methods (XGBoost + LSTM + sentiment)

## 5. Risks

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| `.meta` feature names don't match `compute_technical_analysis()` output keys | Medium | Read `.meta` at startup; log mismatches; fall back to TA-only |
| XGBoost version mismatch between training and inference | Low | Pin `xgboost==1.7.x`; test with each `.pkl` at startup |
| Model predicts UP/DOWN but market moves opposite | Inherent | Confidence threshold gate (≥0.65 to act); HOLD is always safe |
| Feature extraction adds 50–200 ms per request | Known | Feature vector cache eliminates repeat extraction |
