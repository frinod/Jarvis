## 1. Current Implementation Review

### What exists (Phase 6)

| Component | File | Implementation |
|-----------|------|----------------|
| ShortTermMemory | `app/ai/memory/short_term.py` | Ring buffer, session-scoped |
| LongTermMemory | `app/ai/memory/long_term.py` | ABC + `InMemoryLongTermMemory` (dict) |
| EmbeddingService | `app/ai/memory/embeddings.py` | ABC + `SimpleEmbeddingService` (bag-of-words TF) |
| MemoryPipelineProvider | `app/ai/memory/__init__.py` | Wires STM + LTM + embeddings into pipeline |

### Known limitations

1. **InMemoryLongTermMemory** — dict-backed, lost on restart, no persistence.
2. **SimpleEmbeddingService** — bag-of-words TF with unbounded vocabulary growth.
   Cosine similarity degrades as vocab grows. Not semantically meaningful.
3. **Keyword search fallback** — `InMemoryLongTermMemory.search()` is substring
   match only. No ranking beyond importance + recency.
4. **No chunking** — entries are stored whole. Long documents are not split,
   so retrieval precision is low for multi-topic content.
5. **No deduplication** — identical or near-identical entries accumulate.
6. **Importance threshold** — hardcoded at 0.6. No dynamic adjustment.
7. **STM ring buffer** — no summarisation when buffer fills. Oldest turns
   are silently dropped, losing context.
8. **No cross-session memory** — `MemoryPipelineProvider.load()` filters by
   `session_id`, so knowledge from past sessions is never retrieved.

## 2. Research Findings

### 2.1 Short-Term Memory patterns

**Sliding window** (current): simple, predictable, loses old context.

**Summarisation buffer** (GPT-4 / LangChain ConversationSummaryMemory):
- When buffer exceeds N turns, summarise oldest K turns into one entry.
- Preserves semantic content at the cost of one LLM call per compression.
- Suitable for JARVIS: one summarisation call per ~20 turns is acceptable.

**Verdict**: Adopt summarisation buffer in Phase 7. Keep ring buffer as
fallback when no LLM is available.

### 2.2 Long-Term Memory: Vector Databases

Three candidates evaluated against JARVIS constraints
(Python 3.7, Windows, no Docker required for dev, open-source):

| DB | Persistence | Python 3.7 | No Docker (dev) | Semantic search | Notes |
|----|-------------|------------|-----------------|-----------------|-------|
| **Qdrant** | ✅ file-mode | ✅ client 1.x | ✅ in-process | ✅ HNSW | Best fit |
| ChromaDB | ✅ | ✅ | ✅ | ✅ | Simpler API, less mature |
| FAISS | ✅ file | ✅ | ✅ | ✅ | No metadata filtering |
| Weaviate | ✅ | ✅ | ❌ Docker | ✅ | Overkill for Phase 7 |
| Pinecone | ✅ cloud | ✅ | ❌ cloud-only | ✅ | Vendor lock-in |

**Qdrant** in local file mode (`path="./data/qdrant"`) requires no Docker,
persists to disk, supports metadata filtering, and has a stable Python client
that works on Python 3.7+.

### 2.3 Embedding Models

| Model | Size | Quality | Python 3.7 | Offline |
|-------|------|---------|------------|---------|
| `SimpleEmbeddingService` (current) | 0 MB | Poor | ✅ | ✅ |
| `all-MiniLM-L6-v2` (sentence-transformers) | 80 MB | Good | ✅ | ✅ |
| `all-mpnet-base-v2` | 420 MB | Very good | ✅ | ✅ |
| OpenAI `text-embedding-3-small` | API | Excellent | ✅ | ❌ |

**Recommendation**: `all-MiniLM-L6-v2` via `sentence-transformers`. 80 MB,
384-dimensional vectors, runs offline, Python 3.7 compatible. Swap is
transparent — `EmbeddingService` ABC is already in place.

### 2.4 Hybrid Memory Architecture

Research (Lewis et al. 2020, Borgeaud et al. 2022) shows that combining
dense vector retrieval with sparse keyword retrieval (BM25) outperforms
either alone on recall@k metrics.

**Hybrid retrieval**: score = α × dense_score + (1-α) × sparse_score
- α = 0.7 is a common default (dense-weighted).
- Requires both a vector index and a keyword index.
- Qdrant supports sparse vectors natively since v1.7.

### 2.5 Memory Chunking

For long documents (news articles, research summaries):
- Fixed-size chunking (512 tokens, 64-token overlap) is the standard baseline.
- Sentence-boundary chunking preserves semantic units better.
- Phase 7 scope: sentence-boundary chunking for entries > 500 characters.

### 2.6 Cross-Session Memory

Current: `session_id` filter prevents cross-session retrieval.
Fix: store entries with `session_id` as metadata, but search without
session filter. Let importance threshold and semantic score govern retrieval.

## 3. Recommended Architecture for Phase 7

```
MemoryPipelineProvider (unchanged interface)
├── ShortTermMemory          ← add summarisation buffer
├── QdrantLongTermMemory     ← replaces InMemoryLongTermMemory
│   ├── dense index          ← sentence-transformers embeddings
│   └── sparse index         ← BM25 keyword (Qdrant sparse vectors)
└── SentenceTransformerEmbeddingService  ← replaces SimpleEmbeddingService
```

### What does NOT change

- `LongTermMemory` ABC — no changes, `QdrantLongTermMemory` implements it.
- `EmbeddingService` ABC — no changes, new impl drops in.
- `MemoryPipelineProvider` interface — callers unchanged.
- All 1517 existing tests — no modifications needed.

### New files (Phase 7)

| File | Lines (est.) | Purpose |

| `app/ai/memory/qdrant_ltm.py` | ~150 | `QdrantLongTermMemory` |
| `app/ai/memory/sentence_embeddings.py` | ~60 | `SentenceTransformerEmbeddingService` |
| `backend/tests/phase7/test_7_memory.py` | ~120 | Phase 7 memory tests |

## 4. Risks

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| `sentence-transformers` install fails on Python 3.7 | Low | Pin `sentence-transformers==2.2.2`, `transformers==4.30` |
| Qdrant file-mode corruption on Windows | Low | Wrap in try/except, fall back to `InMemoryLongTermMemory` |
| First-load latency (model download ~80 MB) | Medium | Download at startup, log progress, cache in `backend/models/` |
| Qdrant sparse vector API changes | Low | Pin `qdrant-client==1.7.x` |

---

## 5. Decision

**Adopt**: `QdrantLongTermMemory` + `SentenceTransformerEmbeddingService` + summarisation buffer.
**Reject**: ChromaDB (less mature), FAISS (no metadata filtering), cloud-only options.
**Defer to Phase 8**: hybrid BM25+dense retrieval (adds complexity, diminishing returns at Phase 7 scale).
**Defer to Phase 8**: cross-session memory (requires user identity model not yet designed).

See `docs/adr/ADR-002-memory.md` for the formal decision record.
