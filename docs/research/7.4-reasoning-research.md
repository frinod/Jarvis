## 1. Current Implementation Audit

### What exists (Phase 6)

| Component | File | Implementation |
|-----------|------|----------------|
| `ChainOfThought` | `app/ai/reasoning/chain.py` | 5-step pure confidence calculator |
| `Reflection` | `app/ai/reasoning/reflection.py` | Quality checks: length, confidence, stability |
| `ReasoningPlanner` | `app/ai/reasoning/planner.py` | Keyword-based intent classification |
| `PipelineReasonerAdapter` | `app/ai/reasoning/chain.py` | Bridges to `PipelineReasoner` ABC |
| `PipelineVerifierAdapter` | `app/ai/reasoning/reflection.py` | Bridges to `PipelineVerifier` ABC |
| `PipelinePlannerAdapter` | `app/ai/reasoning/planner.py` | Bridges to `PipelinePlanner` ABC |

### Known limitations

1. **`ChainOfThought` produces no LLM reasoning** — all 5 steps are pure
   arithmetic over context counts. The "reasoning" is a confidence score,
   not actual thought.
2. **`ReasoningPlanner._classify_intent()` is keyword-based** — first-word
   matching only. `"Analyse RELIANCE"` → `"analysis"` but `"Give me an
   analysis of RELIANCE"` → `"general"`.
3. **No LLM-generated thought steps** — `ThoughtStep.content` is a template
   string, not LLM output. The LLM is only called in the Responder stage.
4. **Reflection is structural only** — checks chain length and confidence
   drops, not semantic quality of reasoning.
5. **No multi-path reasoning** — single linear chain only. No branching,
   no alternative hypotheses.
6. **`retry_with_critique` template exists but is unused** — the template
   registry has a retry prompt but `ExecutionEngine` does not inject the
   critique back into the next reasoning attempt.

## 2. Research Findings

### 2.1 Chain-of-Thought Prompting (CoT)

**Pattern** (Wei et al., 2022): prompt the LLM to produce intermediate
reasoning steps before the final answer. "Let's think step by step."

**Current state**: JARVIS has the data model (`ThoughtStep`, `thought_chain`)
but the LLM is not asked to produce reasoning steps. The chain is built
from context counts, not LLM output.

**Phase 7 fix**: `SystemPromptBuilder` should include a CoT instruction in
the system prompt for complex requests (analysis, trading decisions). The
LLM's reasoning steps are then parsed back into `ThoughtStep` objects.

**Verdict**: **adopt LLM-generated CoT in Phase 7** for `AnalystAgent` and
`TraderAgent`. Simple requests (questions, general) keep the current
confidence-based chain.

### 2.2 Self-Consistency (SC-CoT)

**Pattern** (Wang et al., 2022): generate multiple independent reasoning
chains, then take the majority vote on the final answer.

**Fit for JARVIS**:
- Requires 3–5 LLM calls per request. High cost for a trading assistant.
- High value for high-stakes decisions (large trade signals).
- `BrainCapabilities.supports_parallel_goals = False` — parallel calls
  not yet supported.

**Verdict**: **defer to Phase 8**. Revisit when parallel goal execution
is enabled and cost model is understood.

### 2.3 Tree of Thoughts (ToT)

**Pattern** (Yao et al., 2023): explore multiple reasoning paths as a tree.
At each node, generate k candidate next thoughts, evaluate them, and prune
low-quality branches. BFS or DFS traversal.

**Fit for JARVIS**:
- Excellent for multi-step planning (portfolio rebalancing, multi-stock
  analysis).
- Requires a separate "evaluator" LLM call at each tree node.
- Significant complexity: tree state management, pruning logic.
- `WorkflowEngine` DAG model is conceptually compatible with ToT branches.

**Verdict**: **defer to Phase 8**. The infrastructure (parallel execution,
multi-agent coordination) must be in place first.

### 2.4 Graph of Thoughts (GoT)

**Pattern** (Besta et al., 2023): generalises ToT to arbitrary graphs.
Thoughts can merge (aggregation) and split (decomposition). Enables
combining insights from multiple reasoning paths.

**Fit for JARVIS**:
- More powerful than ToT but significantly more complex.
- Requires graph traversal infrastructure.
- Low priority until ToT is proven valuable.

**Verdict**: **defer to Phase 9+**.

### 2.5 Reflection / Self-Critique Loops

**Pattern** (Shinn et al., Reflexion 2023): after producing an answer, the
agent critiques its own output and produces a revised answer. Can loop
multiple times.

**Current state**: `Reflection.evaluate()` checks structural quality
(chain length, confidence drops) but does not ask the LLM to critique
its own reasoning.

**Phase 7 enhancement**: add an LLM-based self-critique step for
`TraderAgent` and `AnalystAgent`. The `retry_with_critique` template
already exists in `TemplateRegistry`. Wire it into
`ExecutionEngine._stage_reason()` when `should_retry=True`.

**Verdict**: **adopt LLM-based self-critique in Phase 7**. The template
and retry loop already exist — this is a wiring change, not new
infrastructure.

### 2.6 LLM-Based Intent Classification

**Current**: `ReasoningPlanner._classify_intent()` uses first-word keyword
matching. Misclassifies multi-word intents.

**Phase 7 option A**: expand keyword sets (low effort, limited improvement).
**Phase 7 option B**: use a small LLM call to classify intent (high
accuracy, adds latency).
**Phase 7 option C**: use a local zero-shot classifier
(`facebook/bart-large-mnli` or similar, ~1.6 GB — too large).
**Phase 7 option D**: use the existing LLM with a structured prompt
(e.g., "Classify this request as one of: question/task/analysis/trading/general").

**Verdict**: **adopt option D in Phase 7** — one small LLM call at the
planning stage with a structured classification prompt. Adds ~100–200 ms
but eliminates misclassification. Falls back to keyword matching if LLM
unavailable.

### 2.7 Structured Output / JSON Mode

Modern LLMs support JSON-mode output (Gemini, GPT-4, Groq). This allows
the reasoning chain to be returned as structured JSON rather than parsed
from free text.

**Fit for JARVIS**:
- `LLMGateway` can pass `response_format={"type": "json_object"}` for
  supported providers.
- `ChainOfThought` can parse the JSON response into `ThoughtStep` objects.
- Eliminates fragile text parsing.

**Verdict**: **adopt JSON-mode reasoning output in Phase 7** for providers
that support it. Fallback: text parsing for Ollama.

## 3. Recommended Architecture for Phase 7

```
ExecutionEngine._stage_plan()
  └── LLMPlannerAdapter.plan(ctx)       ← Phase 7: LLM intent classification
        └── LLMGateway.complete(        ← structured prompt: classify intent
              "Classify: question/task/analysis/trading/general"
            )
        └── ctx.intent_type = result    ← replaces keyword matching

ExecutionEngine._stage_reason()
  └── LLMReasonerAdapter.reason(ctx)    ← Phase 7: LLM-generated CoT
        └── SystemPromptBuilder         ← includes "think step by step" instruction
        └── LLMGateway.complete()       ← returns JSON reasoning chain
        └── parse → ctx.thought_chain   ← ThoughtStep objects from LLM output

  └── PipelineVerifierAdapter.verify()  ← structural checks (unchanged)
        └── if should_retry:
              └── inject critique into ctx.metadata
              └── re-run LLMReasonerAdapter with retry_with_critique template
```

### What does NOT change

- `ChainOfThought` class — kept as fallback when no LLM available.
- `Reflection` class — structural checks remain, LLM critique is additive.
- `PipelineReasoner` / `PipelineVerifier` ABCs — no changes.
- All existing tests — no modifications needed.

## 4. Phase 7 vs Phase 8 Scope

### Phase 7
- LLM-generated CoT for `AnalystAgent` and `TraderAgent`
- LLM-based intent classification (structured prompt)
- LLM self-critique loop (wire existing `retry_with_critique` template)
- JSON-mode reasoning output for supported providers

### Phase 8+
- Self-Consistency (SC-CoT) — multiple chains, majority vote
- Tree of Thoughts — requires parallel execution infrastructure
- Graph of Thoughts — requires ToT first
- DSPy prompt optimisation — requires labelled outcome data

## 5. Risks

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| LLM intent classification adds 100–200 ms latency | Certain | Cache classification for identical inputs; keyword fallback |
| JSON-mode not supported by Ollama | Known | Text-parsing fallback in `LLMReasonerAdapter` |
| LLM self-critique loop increases token usage | Medium | Cap at 1 critique retry; configurable via `ExecutionPolicySpec` |
| CoT reasoning diverges from actual tool results | Low | `Reflection` structural checks catch confidence drops |
