## 2. Research Findings

### 2.1 What "Learning" Means for JARVIS

Three distinct learning types are relevant:

| Type | Description | Phase |
|------|-------------|-------|
| **Episodic memory** | Store outcomes of past requests in LTM | 7 (infrastructure) |
| **Feedback learning** | Adjust agent behaviour based on user feedback | 8 |
| **Model retraining** | Update XGBoost models with new trade outcomes | 8+ |

Phase 7 scope: build the **outcome recording infrastructure** that Phase 8
learning will consume. No actual learning algorithms in Phase 7.

### 2.2 Outcome Recording

For learning to work, every agent decision needs an outcome record:
- What was the input (goal, context)?
- What was the decision (signal, response)?
- What was the outcome (trade result, user feedback)?
- When did the outcome become known?

**Phase 7**: define an `OutcomeRecord` dataclass. `BaseAgent.learn()` is
called with an `OutcomeRecord` when an outcome is known. Implementations
store the record to `LongTermMemory` with `entry_type="outcome"`.

This is the minimum infrastructure Phase 8 needs. No learning algorithm
is implemented — just recording.

### 2.3 Reflection → Action Items

`Brain.reflect()` already produces `ActionItem` objects:
- `"increase_memory_scope"` — load more context next time
- `"review_tool_reliability"` — a tool failed
- `"lower_confidence_threshold"` — objective not achieved
- `"store_to_long_term_memory"` — high-confidence result

**Current state**: `ActionItem` objects are stored in `_reflection_log`
but never acted upon. They are produced and discarded.

**Phase 7**: implement an `ActionItemExecutor` that processes `ActionItem`
objects after each request. Phase 7 scope: only `"store_to_long_term_memory"`
is acted upon (store the result to LTM). Other action items are logged for
Phase 8.

**Verdict**: **implement `ActionItemExecutor` with LTM storage only in Phase 7**.

### 2.4 Confidence Calibration

`Brain._aggregate_confidence()` uses fixed weights from `ExecutionPolicySpec`.
Over time, these weights should be adjusted based on which sources
(reasoner, skills, tools) are most predictive of actual outcomes.

**Phase 7**: record `(source_weights, final_confidence, outcome)` tuples
in LTM. Phase 8: use these records to calibrate weights via Platt scaling
or isotonic regression.

**Verdict**: **record calibration data in Phase 7, calibrate in Phase 8**.

### 2.5 Reinforcement Learning from Human Feedback (RLHF)

**Pattern**: user provides thumbs up/down on responses; model is fine-tuned
to prefer approved responses.

**Fit for JARVIS**:
- Requires a fine-tunable model (not applicable to API-based providers).
- Applicable to Ollama local models in Phase 8+.
- Requires significant labelled data collection first.

**Verdict**: **defer to Phase 9+**.

### 2.6 In-Context Learning (ICL)

**Pattern**: include few-shot examples of good decisions in the system
prompt. The LLM "learns" from examples without weight updates.

**Fit for JARVIS**:
- Immediately applicable — no training required.
- Examples stored in LTM with `entry_type="example"`.
- Retrieved via RAG and injected into the system prompt.
- Effective for `TraderAgent`: "Here are 3 past trades that worked well..."

**Verdict**: **adopt ICL in Phase 7** as the primary learning mechanism.
Store high-confidence outcomes as examples in LTM. Retrieve and inject
via the RAG pipeline (7.2).

### 2.7 `core/learning.py` Assessment

This file exists in `app/core/` (kernel zone — ACP required for changes).
It is not read yet but is likely a legacy learning stub from pre-Phase 6.
Phase 7 learning infrastructure lives in `app/ai/` only. No changes to
`app/core/learning.py` without ACP.

## 3. Recommended Architecture for Phase 7

```
Brain.process() completes
  └── Brain.reflect(goal, result, policy)
        └── ReflectionResult.action_items
              └── ActionItemExecutor.execute(action_items, result)
                    └── "store_to_long_term_memory":
                          └── LTM.store(MemoryEntry(
                                content=result.response,
                                entry_type="outcome",
                                importance=result.confidence,
                                metadata={"goal": goal.objective, "confidence": result.confidence}
                              ))
                    └── "store_example" (if confidence >= 0.85):
                          └── LTM.store(MemoryEntry(
                                entry_type="example",
                                content=f"Q: {goal.objective}\nA: {result.response}"
                              ))
                    └── other action items: log only (Phase 8)

RAG retrieval (7.2) includes entry_type="example" in context
  └── SystemPromptBuilder injects examples as few-shot context
```

### What does NOT change

- `Brain.reflect()` — no changes.
- `BaseAgent.learn()` — implementations change from `pass` to `OutcomeRecord` storage.
- `BrainCapabilities.supports_learning` — stays `False` (full learning not enabled).
- All existing tests — no modifications needed.

## 4. Phase 7 vs Phase 8 Scope

### Phase 7 (infrastructure only)
- `OutcomeRecord` dataclass
- `ActionItemExecutor` (LTM storage + example storage only)
- In-context learning via example retrieval (RAG pipeline)
- Calibration data recording (no calibration algorithm)

### Phase 8 (actual learning)
- `BrainCapabilities.supports_learning = True`
- Confidence weight calibration (Platt scaling)
- User feedback loop (thumbs up/down → example store)
- `BaseAgent.learn()` full implementations
- DSPy prompt optimisation using outcome records

### Phase 9+
- RLHF for local Ollama models
- XGBoost model retraining from trade outcomes
- Online learning / continual learning

## 5. Risks

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| LTM fills with low-quality examples | Medium | Importance threshold ≥ 0.85 for example storage |
| ICL examples increase prompt token usage | Medium | Cap at 3 examples; token budget from 7.2 applies |
| `ActionItemExecutor` adds latency to every request | Low | Fire-and-forget async; no await on LTM write |
