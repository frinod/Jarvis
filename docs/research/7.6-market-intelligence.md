### What exists (Phase 6)

| Component | File | State |
|-----------|------|-------|
| `MarketPerception` ABC | `app/ai/perception/market.py` | Interface only |
| `InMemoryMarketPerception` | `app/ai/perception/market.py` | Returns mock dict |
| `NewsPerception` ABC | `app/ai/perception/news.py` | Interface only |
| `InMemoryNewsPerception` | `app/ai/perception/news.py` | Returns mock `NewsItem` list |
| `SentimentPerception` ABC | `app/ai/perception/sentiment.py` | Interface only |
| `InMemorySentimentPerception` | `app/ai/perception/sentiment.py` | Averages `NewsItem.sentiment` |

| Yahoo Finance provider | `app/market_data/providers/yahoo.py` | Fallback data source |
| Market news | `app/api/market_intelligence.py` | `get_market_news()` |

### Key observation

The live market intelligence pipeline already exists and works — it lives
in `JarvisOrchestrator._fetch_stock_context()` and `_fetch_market_news_context()`.
The Phase 6 AI runtime (`MarketPerception`, `NewsPerception`) is a parallel
stub that is never connected to the live pipeline.

**The Phase 7 task is not to build market intelligence from scratch — it is
to bridge the existing live pipeline into the AI runtime.**

### Known limitations

1. **`InMemoryMarketPerception` is never connected to Angel One / Yahoo** —
   the live data flows through `JarvisOrchestrator`, not through the AI
   runtime perception layer.
2. **Perception data is not stored to `LongTermMemory`** — market snapshots
   and news items are fetched, used once, and discarded. No historical
   context accumulates.
3. **`SentimentPerception` averages mock `NewsItem.sentiment` values** —
   no real NLP sentiment analysis.
4. **No structured market event detection** — price breakouts, volume spikes,
   RSI extremes are detected in `compute_technical_analysis()` but not
   surfaced as typed events to the AI runtime.
5. **`AnalystAgent` and `TraderAgent` cannot access live market data** —
   they only see `ExecutionContext.metadata`, which is populated by the
   orchestrator before the AI runtime is called.

## 2. Research Findings

### 2.1 Bridging the Live Pipeline

The cleanest Phase 7 approach is to implement `MarketPerception` and
`NewsPerception` as thin wrappers around the existing live data functions.

**`AngelOneMarketPerception`**:
- Wraps `fetch_candles()` from `app/market_data/service.py`.
- Wraps `compute_technical_analysis()` from `app/api/technical_analysis.py`.
- Returns a `PerceptionBundle` with the full TA dict as `data`.

**`LiveNewsPerception`**:
- Wraps `get_market_news()` from `app/api/market_intelligence.py`.
- Maps news items to `NewsItem` objects with sentiment scores.

This approach:
- Reuses all existing live data infrastructure.
- Requires no new external dependencies.
- Gives `AnalystAgent` and `TraderAgent` access to live data via the
  standard `PerceptionBundle` interface.

**Verdict**: **implement bridge implementations in Phase 7**.

### 2.2 Perception-to-Memory Pipeline

As identified in 7.2 RAG Research, perception data should be stored to
`LongTermMemory` after each request. This enables:
- Historical market context retrieval ("What was RELIANCE doing last week?")
- Pattern detection across sessions
- `TraderAgent` learning from past market states

**Implementation**: at the end of `ExecutionEngine._stage_respond()` (or
in a new `_stage_persist()` stage), store `PerceptionBundle.data` as a
`MemoryEntry` with `entry_type="market_snapshot"` and `entry_type="news"`.

**Verdict**: **implement perception-to-LTM pipeline in Phase 7**.

### 2.3 Market Event Detection

`compute_technical_analysis()` already detects:
- Candlestick patterns (hammer, doji, engulfing, etc.)
- Chart patterns (head & shoulders, double top, etc.)
- RSI overbought/oversold
- MACD crossovers
- Volume anomalies

These are returned as lists in the TA dict but are not surfaced as typed
events to the AI runtime.

**Phase 7**: define a `MarketEvent` dataclass with `event_type`, `symbol`,
`severity`, `description`. `AngelOneMarketPerception.fetch()` parses the
TA dict and emits `MarketEvent` objects in `PerceptionBundle.metadata`.

**Verdict**: **implement `MarketEvent` in Phase 7** as a lightweight
structured signal. Agents can check `bundle.metadata["events"]` for
actionable signals.

### 2.4 Sentiment Analysis

**Current**: `InMemorySentimentPerception` averages `NewsItem.sentiment`
values that are manually set (mock data).

**Options**:
- **A**: Use the LLM to score sentiment for each news headline. Accurate,
  adds latency and token cost.
- **B**: Use a local sentiment model (`cardiffnlp/twitter-roberta-base-sentiment`,
  ~500 MB). Offline, fast, Python 3.7 compatible.
- **C**: Use keyword-based VADER sentiment (no model, ~1 MB). Fast, less
  accurate for financial text.
- **D**: Use the sentiment already returned by `get_market_news()` — the
  existing news API already returns a `sentiment` field.

**Verdict**: **adopt option D in Phase 7** — use the sentiment already
present in `get_market_news()` response. Zero new dependencies. Options B
and C deferred to Phase 8 for improved accuracy.

### 2.5 Real-Time vs Batch Perception

**Current**: perception is fetched on-demand per request (pull model).

**Phase 7**: keep pull model. Each `AnalystAgent` or `TraderAgent` request
triggers a fresh `MarketPerception.fetch()` call.

**Phase 8**: push model — a background scheduler fetches market data every
N minutes and stores to LTM. Agents retrieve from LTM instead of fetching
live. This reduces latency and API call frequency.

**Verdict**: **keep pull model in Phase 7**. Push model deferred to Phase 8.

### 2.6 Angel One Integration

`AngelOneMarketPerception` wraps the existing `angel_one.py` provider.
The Angel One provider already handles authentication, session management,
and rate limiting. No new Angel One integration work is needed.

**Phase 7 scope**: implement the `MarketPerception` ABC wrapper only.
The underlying Angel One provider is unchanged.

## 3. Recommended Architecture for Phase 7

```
AnalystAgent.execute(ctx)
  └── AngelOneMarketPerception.fetch({"symbol": symbol})
        └── fetch_candles(symbol, interval="15m", days=5)
        └── compute_technical_analysis(candles)
        └── parse MarketEvent list from TA dict
        └── return PerceptionBundle(data=ta_dict, metadata={"events": events})
  └── LiveNewsPerception.fetch({"query": symbol, "limit": 5})
        └── get_market_news(symbol=symbol, limit=5)
        └── return List[NewsItem] with sentiment from API
  └── InMemorySentimentPerception.score() ← uses NewsItem.sentiment from API
  └── FeatureStore.build_from_bundle(bundle)
  └── XGBoostForecastingEngine.predict(features)
  └── ConfidenceScorer.score(prediction, ta_signal, sentiment)

ExecutionEngine._stage_persist() [new, optional]
  └── store PerceptionBundle → LTM as entry_type="market_snapshot"
  └── store NewsItems → LTM as entry_type="news"
```

### What does NOT change

- `MarketPerception` ABC — no changes.
- `NewsPerception` ABC — no changes.
- `SentimentPerception` ABC — no changes.
- `PerceptionBundle` data model — `metadata["events"]` is additive.
- All existing tests — no modifications needed.

## 4. Phase 7 vs Phase 8 Scope

### Phase 7
- `AngelOneMarketPerception` bridging live TA pipeline
- `LiveNewsPerception` bridging `get_market_news()`
- `MarketEvent` structured signal detection
- Perception-to-LTM storage pipeline
- Sentiment from existing API response

### Phase 8+
- Push model (background scheduler, LTM-first retrieval)
- Local NLP sentiment model (VADER or RoBERTa)
- Multi-symbol batch perception
- Options chain perception (if Angel One provides it)
- Macro economic indicators (RBI rates, FII/DII flows)

## 5. Risks

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| Angel One API rate limits during multi-agent requests | Medium | Cache `PerceptionBundle` per symbol per minute |
| `compute_technical_analysis()` returns error for thin data | Known | `PerceptionBundle.success=False`; agent falls back to TA-only confidence |
| News API returns empty for some symbols | Medium | `LiveNewsPerception` returns empty list; `ConfidenceScorer` uses TA-only weights |
| Perception-to-LTM adds latency to every request | Low | `_stage_persist()` is fire-and-forget (no await on result) |
